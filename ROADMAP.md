## ✅ Этап 0.5.0 — «Доверие данным» (выпущен 10.08.2026; ждёт полевой проверки владельцем)

Тема: пользователь должен быть уверен, что данные никогда не пропадут
и любую запись можно исправить.

1. **Версионирование состояния** — СДЕЛАНО: `STATE_SCHEMA_VERSION` (=2),
   точка миграций `migrateStateSchema`, номер схемы в бэкапе all-profiles
   (фундамент SQLite).
2. **Редактирование записей** — СДЕЛАНО: еда (название/ккал/БЖУ), активность
   (вид/время/заметка/дата), вес (✏️ в истории). Вода — через «Поправить день».
3. **Записи задним числом** — СДЕЛАНО: дата в форме активности + диалог
   «Поправить итог дня» (вода/ккал/минуты прошлого дня).
4. **Системный undo** — СДЕЛАНО для точечных операций (снекбар 6,5 с);
   массовые операции (импорт/сброс) намеренно за подтверждающими диалогами.
5. **Онбординг-lite** — СДЕЛАНО: три экрана переписаны под текущие реалии.
6. **Доступность (a11y-pass)** — БАЗОВО: :focus-visible + aria у новых
   контролов; полный TalkBack-проход остаётся в POSTPONED P19.
7. **Каркас PRO-разблокировки** (см. «Монетизация» ниже) — РЕШЕНИЕ ВЛАДЕЛЬЦА:
   «закладывай, пусть будет» → реализован в 0.5.1 (экран + офлайн-коды +
   флаг в бэкапе, БЕЗ ограничений функций).

Кандидаты из анализов, ожидающие решения: `POSTPONED.md` P13–P24.

## ✅ Этап 0.6.0 — Внедрение SQLite (выпущен 11.08.2026)

- Полнофункциональная реляционная база данных SQLite (`sql.js` 1.14.1 WASM + IndexedDB binary).
- Полная независимость: работает 100% офлайн без нативных плагинов и правок workflow.
- Архитектура Dual-Write: каждый `saveState()` сохраняет состояние в `localStorage` и асинхронно синхронизирует реляционные таблицы SQLite (`meta`, `profiles`, `states`, `daily_summaries`, `food_entries`, `workout_entries`, `weight_entries`, `custom_foods`, `combos`).
- Автоматический резервный снимок `fitflow:pre-sqlite-backup` перед миграцией.
- Автоматический откат на `localStorage` при любой ошибке.

## Этап 0.8.0 — «Дневник тренировок» (упражнения, веса × подходы × повторы, баланс активности)

Отдельный раздел-дневник ВНУТРИ FitFlow (не отдельное приложение и не
«полуклон» — синергия с водой/питанием/весом/ИИ важнее изоляции):

- План тренировок: силовые и кардио; «в зале» или «дома» (дом — инвентарь
  ограничен, упражнения подбираются соответственно); веса × подходы × повторы.
- Расписание на конкретные дни: приложение само предлагает тренировку дня;
  её можно перенести на другой день или поменять местами.
- Динамика весов и повторов: история по упражнениям, графики прогресса по
  ВЫБРАННЫМ упражнениям (пользователь отмечает, какие отслеживать; количество
  ограничено, чтобы графики не превращались в кашу) — уточнение владельца
  10.08.2026: «активность есть активность», а спортивный прогресс живёт здесь,
  в дневнике, отдельно от бытовой активности.
- Связка с «Активностью»: отмеченная пройденной тренировка переносится
  в раздел активности (минуты/ккал) — строго без двойного счёта.
- ИИ-анализ тренировок (0.7.x): разбор прогресса и рекомендации по весам
  и программе с учётом дома/зала; цифры считают алгоритмы — объясняет ИИ.
- Почему после SQLite (0.6.0): многолетние истории подходов и весов — именно
  тот профиль данных, ради которого делается миграция. С часами полезно,
  но ручной ввод — полноценный базовый сценарий навсегда.

## Этап 0.8.0 — нативный этап: шаги телефона + Health Connect (идея владельца, 10.08.2026)

- Шаги по самому телефону (датчики TYPE_STEP_COUNTER / TYPE_STEP_DETECTOR):
  из WebView недоступны, Generic Sensor API их не включает — нужен нативный

  нормы и анализ. Импорт шагов телефона и Health Connect — общий контур,
  чтобы не писать два параллельных.
- Оба импорта — только как «плюс» к ручному вводу: окно «сегодня», явное
  правило против двойного счёта с ручными записями активности.
- Приоритет источников (уточнение владельца 10.08.2026): телефон и браслет/
  часы могут считать шаги ОДНОВРЕМЕННО — данные двух трекеров никогда не
  суммируются. Один источник на метрику за день: «Авто» = Health Connect
  (часы/браслет), если за день данных нет — датчики телефона; переключатель

  источник («шаги: часы»), чтобы значения не завышались и не занижались
  незаметно. Ручные записи активности — всегда отдельное честное слагаемое.
- Шаги идут В ОБЩИЙ ЗАЧЁТ активности (решение владельца 10.08.2026 вместо ранее
  записанной «отдельной метрики»): никакой параллельной шкалы «шаги vs активность»;

  в приложении уже говорит об этом (0.5.6).
- «⚙️ Настроить» для нативного уведомления воды (рядом с «+250 мл») —

## 💰 Монетизация (статус: РЕШЕНО 10.08.2026 — бесплатно навсегда + добровольная поддержка)

Фактура, найденная владельцем: в RuStore монетизацию подключают только
юридические лица (физлицам оплата через магазин недоступна); платежи
Google Play в РФ недоступны; даже бесплатная публикация в RuStore требует
полной верификации физлица (паспорт, фото, доп. сведения) — поэтому RuStore
на текущий момент отложен, основной канал распространения — GitHub Releases.

Решение: приложение остаётся бесплатным и полноценным навсегда; раздел
«FitFlow PRO» (0.5.1) — только добровольная поддержка разработки, никакие
функции кодом не открываются.

Рабочие правовые заметки владельца (НЕ юридическая консультация; при оборотах —
налоговый консультант):
- Приём переводов только через российские банки/СБП — фильтрация по 115-ФЗ
  выполняется банком; крипту от неизвестных не принимать.
- При поступлениях — регистрация НПД (самозанятость, «Мой налог», 4–6 %):
  корректная форма для «поддержки с благодарностью (PRO-статус)»; чистое
  дарение денег между физлицами НДФЛ не облагается, но встречное предоставление
  делает перевод оплатой — НПД снимает этот риск.
- Подозрительный перевод — вернуть отправителю тем же способом; назначение
  платежа — «добровольная поддержка проекта FitFlow».

Принципы (зафиксированы ранее в PROJECT.md # 2): бесплатное ядро навсегда;
без серверов, подписок и аккаунтов; полный офлайн.

**Инженерное предложение — офлайн-PRO-каркас:**
- Владелец генерирует коды ВНЕ приложения: `HMAC(секрет, личная строка
  покупателя — имя/e-mail)` → короткий код. Секрет есть только у владельца
  (в репозитории — только публичная проверочная часть).
- Экран «Разблокировать»: ввод кода → локальная проверка подписи →
  флаг `proUnlocked` в state, **входящий в резервную копию all-profiles**.
- Вопрос владельца «что при удалении/переносе на другой телефон»:
  код привязан к ЛИЧНОЙ СТРОКЕ, а не к устройству → на новом телефоне
  вводится тот же код заново (или PRO восстанавливается вместе с бэкапом).
- Честно: это защита от случайного копирования и «добросовестного
  пользователя», а не DRM — взломать можно, цель её не в этом.
