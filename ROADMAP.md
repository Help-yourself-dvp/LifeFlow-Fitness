## ✅ Этап 0.6.0 — Внедрение SQLite (выпущен 11.08.2026)

- Полнофункциональная реляционная база данных SQLite (`sql.js` 1.14.1 WASM + IndexedDB binary).
- Полная независимость: работает 100% офлайн без нативных плагинов и правок workflow.
- Архитектура Dual-Write: каждый `saveState()` сохраняет состояние в `localStorage` и асинхронно синхронизирует реляционные таблицы SQLite (`meta`, `profiles`, `states`, `daily_summaries`, `food_entries`, `workout_entries`, `weight_entries`, `custom_foods`, `combos`).
- Автоматический резервный снимок `fitflow:pre-sqlite-backup` перед миграцией.
- Автоматический откат на `localStorage` при любой ошибке.

## 📱 План по разработке под iOS (iPhone / iPad)

Благодаря архитектуре FitFlow (Offline-first HTML5 / Vanilla JS / SQLite WASM + IndexedDB) приложение на 90% кроссплатформенно. Ниже 4 пути реализации под экосистему Apple:

### 1. PWA (Progressive Web App) через Safari — пробный бесплатный формат
- **Как работает**: публикация веб-сборки на GitHub Pages. Пользователь открывает в Safari ➔ «Поделиться» ➔ «На экран "Домой"».
- **Плюсы**: $0 затрат, без аккаунта Apple Developer ($99/год), работает полностью офлайн (Service Worker + IndexedDB / SQLite WASM).
- **Ограничения iOS**:
  - Нет нативных виджетов рабочего стола iOS.
  - Локальные уведомления без сервера в iOS PWA сильно ограничены.
  - Safari может очищать кэш при нехватке памяти при редком использовании (требуется регулярный бэкап JSON).

### 2. SideStore / AltStore — нативный IPA без джейлбрейка
- **Как работает**: сборка `.ipa` через GitHub Actions (на раннере macOS). Установка на iPhone через SideStore с бесплатным личным Apple ID.
- **Преимущество SideStore**: самообновление 7-дневного бесплатного сертификата Apple прямо с телефона по Wi-Fi через локальный WireGuard VPN (компьютер нужен только один раз при первичной установке).
- **Плюсы**: полноценное нативное приложение, поддержка локальных уведомлений, фоновой работы и нативных мостов.

### 3. Интеграция с Apple Health (HealthKit)
- **Мост данных**: плагин `@capacitor-community/health-kit` или кастомный Swift-мост.
- **Метрики**:
  - Чтение шагов (`HKQuantityTypeIdentifierStepCount`) с iPhone и Apple Watch.
  - Чтение объективного сна (`HKCategoryTypeIdentifierSleepAnalysis`).
  - Чтение активной энергии (`HKQuantityTypeIdentifierActiveEnergyBurned`).
- **Алгоритм Master Priority**: `MAX(Apple_HealthKit, Шагомер_Телефона)`.

### 4. Официальная публикация в App Store / TestFlight (финальный этап)
- Требует: Apple Developer Program ($99/год), прохождение App Store Review, политика конфиденциальности.

## 💰 Монетизация (статус: РЕШЕНО 10.08.2026 — бесплатно навсегда + добровольная поддержка)

Фактура, найденная владельцем: в RuStore монетизацию подключают только
юридические лица (физлицам оплата через магазин недоступна); платежи
Google Play в РФ недоступны; даже бесплатная публикация в RuStore требует
полной верификации физлица (паспорт, фото, доп. сведения) — поэтому RuStore
на текущий момент отложен, основной канал распространения — GitHub Releases.

Решение: приложение остаётся бесплатным и полноценным навсегда; раздел
«FitFlow PRO» (0.5.1) — только добровольная поддержка разработки, никакие
функции кодом не открываются.

Рабочие правовые заметки владельца (НЕ юридическая консультация; при оборотах —
налоговый консультант):
- Приём переводов только через российские банки/СБП — фильтрация по 115-ФЗ
  выполняется банком; крипту от неизвестных не принимать.
- При поступлениях — регистрация НПД (самозанятость, «Мой налог», 4–6 %):
  корректная форма для «поддержки с благодарностью (PRO-статус)»; чистое
  дарение денег между физлицами НДФЛ не облагается, но встречное предоставление
  делает перевод оплатой — НПД снимает этот риск.
- Подозрительный перевод — вернуть отправителю тем же способом; назначение
  платежа — «добровольная поддержка проекта FitFlow».

Принципы (зафиксированы ранее в PROJECT.md # 2): бесплатное ядро навсегда;
без серверов, подписок и аккаунтов; полный офлайн.

**Инженерное предложение — офлайн-PRO-каркас:**
- Владелец генерирует коды ВНЕ приложения: `HMAC(секрет, личная строка
  покупателя — имя/e-mail)` → короткий код. Секрет есть только у владельца
  (в репозитории — только публичная проверочная часть).
- Экран «Разблокировать»: ввод кода → локальная проверка подписи →
  флаг `proUnlocked` в state, **входящий в резервную копию all-profiles**.
- Вопрос владельца «что при удалении/переносе на другой телефон»:
  код привязан к ЛИЧНОЙ СТРОКЕ, а не к устройству → на новом телефоне
  вводится тот же код заново (или PRO восстанавливается вместе с бэкапом).
- Честно: это защита от случайного копирования и «добросовестного
  пользователя», а не DRM — взломать можно, цель её не в этом.
- Кандидаты в PRO (обсуждаемо, ядро не трогаем): локальные «тяжёлые» ИИ-модели,
  расширенные темы, «Мой курс»-плюс, расширенная аналитика.

Реализация каркаса (экран + флаг + генератор кодов для владельца) — выполнена
в 0.5.1 (решение владельца), детали — в записи 0.5.1 раздела # 14 PROJECT.md.

Каналы роста (вопрос владельца «а как люди узнают?», 10.08.2026): GitHub сам
по себе не воронка — он «причал», куда ведут ссылки. Воронки: ① подача
бесплатной сборки в RuStore после стор-чеклиста выше (верификация разовая;
PRO-экран правилам не противоречит — он ничего не продаёт); ② посты в
тематических Telegram-каналах и ветка приложения на 4PDA; ③ статья на Хабре
(офлайн-приватность + умный ввод — читаемая история); ④ Obtainium для
технической аудитории (сам следит за GitHub Releases). В приложении —
плашка поддержки (0.5.3, редко-повторяемая с 0.5.4) и социальный механизм
«поделись с тем, кому полезно»: рассмотреть отдельным пунктом позже.

Статус каналов роста (решение владельца 10.08.2026): **ЗАМОРОЖЕНО** до
отдельного решения. Аргументы: объём персональных данных KYC-верификации
RuStore неприемлем для бесплатной публикации; 4PDA — вероятные ограничения
для новых аккаунтов (создание тем после истории/репутации) и узкая
«целевая» аудитория; публикация — не спринт, сначала продукт для себя
и близких. Практический канал по-прежнему один — GitHub Releases.
