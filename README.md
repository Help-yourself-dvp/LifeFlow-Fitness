# LifeFlow-Fitness — FitFlow (фитнес-трекер)

Мобильное приложение на базе **Capacitor/WebView** (Android), offline-first, без обязательной регистрации.
Все данные хранятся локально на устройстве.

> Репозиторий объединяет два будущих приложения: **FitFlow** (фитнес-трекер) и **LifeOps** (универсальный помощник).
> Сейчас в разработке — **FitFlow**.

Актуальная версия: **0.9.53** — история изменений в [CHANGELOG.md](CHANGELOG.md), дорожная карта в [ROADMAP.md](ROADMAP.md), конфиденциальность в [PRIVACY.md](PRIVACY.md), полное текстовое описание приложения в [APP_DESCRIPTION.md](APP_DESCRIPTION.md).

## Как смотреть приложение в браузере (без установки APK)

Приложение — это обычные HTML/CSS/JS, поэтому оно работает в любом браузере:

```bash
# 1) Просто открыть файл
open index.html          # macOS
xdg-open index.html      # Linux

# 2) Или поднять локальный сервер (рекомендуется)
npx serve .
# затем открыть http://localhost:3000
```

Готовые скриншоты интерфейса лежат в `previews/` — можно оценить дизайн без запуска.

## Тесты

node test-parser.js    # парсер, база, активность, утренние фразы (318 проверок)

## Сборка и скачивание APK (GitHub Actions)

Проект настроен на автоматическую сборку Android APK при каждом пуше в репозиторий:
1. Во вкладке **Actions** на GitHub выберите workflow **Build Native Android APK** или откройте последний запуск.
2. В разделе **Artifacts** скачайте архив **FitFlow-APK** (содержит `app-debug.apk` и `FitFlow-v<версия>-debug.apk`; номер версии сборка читает из `version.txt`).
3. Для сохранения постоянной подписи (чтобы обновлять приложение поверх без удаления данных):
   - Запустите workflow **Generate Stable Debug Keystore** (вкладка Actions).
   - Скопируйте содержимое сгенерированного файла `debug.keystore.base64.txt` в секреты репозитория (**Settings → Secrets and variables → Actions**) под именем `DEBUG_KEYSTORE_BASE64`.

## Стек

- Чистые HTML/CSS/JS (без фреймворков — минимум зависимостей, быстро и надёжно в WebView)
- Material 3 (цветовые токены `--md-sys-color-*`)
- localStorage + SQLite (sql.js WebAssembly в IndexedDB, Dual-Write) — локально, без сервера
- Парсер текстового ввода еды с локальной базой 960+ продуктов (ккал на 100 г / на штуку)
- Нативный плагин `fitflow-local-ai` (LiteRT-LM) для нейросети Gemma на устройстве
- Источники и лицензии пищевых данных: [DATA_SOURCES.md](DATA_SOURCES.md)
- Разбор «еда по фото: что реально возможно» (варианты без ключа и без тяжёлой модели): [PHOTO_AI_ANALYSIS.md](PHOTO_AI_ANALYSIS.md)
- `@capacitor/local-notifications` для напоминаний (вода, приёмы пищи, вечерняя активность, утренняя мотивация)

## Заметки по ограничениям РФ

- ИИ-провайдеры (нейросеть на устройстве; облако: Gemini, DeepSeek, OpenRouter, GigaChat) подключаются **только по желанию пользователя**
  и как дополнение к локальному парсеру — приложение полноценно работает без них.
- Никаких обязательных регистраций и облачных аккаунтов.
- Ограничения бесплатных API (лимиты запросов/день) не критичны, т.к. ИИ не является
  обязательным путём выполнения основной логики.
