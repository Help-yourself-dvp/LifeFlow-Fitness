# FitFlow — полное описание приложения

**Актуально для версии: 0.8.6 (сборка подставляется автоматически).**

**Назначение файла.** Единый текстовый «слепок» интерфейса: какие экраны, карточки,
кнопки и диалоги существуют, что на них написано, где расположены и что происходит
при взаимодействии. Документ заменяет скриншоты каждого элемента: по нему ИИ (или
новый участник команды) понимает реальную структуру приложения без запуска.

**Правило поддержки (обязательное).** При каждом изменении интерфейса (новая кнопка,
текст, перестановка, удаление) этот файл обновляется В ТОМ ЖЕ релизе, а строка
«Актуально для версии» приводится к текущей. Актуальность версии проверяется
автотестом `test-ui-init.js`. Если описание и код разошлись — правда в коде,
а файл надо поправить немедленно.

**Как читать id.** В скобках у элементов указаны реальные `id`/`class` из `index.html`
и `app.js` — по ним удобно искать в коде. Все тексты приведены дословно (в кавычках).

## 0. Общая модель

- Приложение — одностраничное: `index.html` + `style.css` + `app.js` (без фреймворков),
  внутри Android-оболочки Capacitor 5.7.0 (пакет `com.fitflow.app`).
- Экраны («виды») — заранее отрисованные `<div hidden>`: переключение видов просто
  снимает `hidden` и показывает нужный (функция `switchView`), поэтому переходы мгновенные.
  Список видов: `home-view`, `stats-view`, `water-details-view`, `food-details-view`,
  `weight-details-view`, `training-view`, `settings-view`, подэкраны настроек
  `settings-general-view`, `settings-profile-view`, `settings-notifications-view`,
  `settings-courses-view`, `settings-ai-view`, `settings-data-view`, `settings-about-view`,
  `game-medals-view`, `notifications-view`, `ai-view`.
- Диалоги — обёртки `.app-dialog-backdrop` поверх интерфейса; системная кнопка «назад»
  закрывает самый верхний открытый (обработчик `handleBackNavigation`). Исключение —
  окно условий при первом запуске: «назад» его не обходит.
- Визуальная обратная связь о действии — всплывающий тост `#toast` внизу экрана
  (функция `toast(...)`): появляется на ~2,5 с и исчезает сам.
- Всё хранится локально в `localStorage` (ключи вида `fitflow:*`); аккаунта и сервера нет.
- Темы: светлая/тёмная/авто (`data-theme`), поверх — 5 стилей-палитр
  (Стандарт / Neon / Sport / Лес / Виноград) и 3 шрифта (Стандарт / Узкий / Книжный).

## 1. Шапка приложения (`header.topbar`)

Постоянно сверху, на всех «домашних» видах.

Слева — логотип (круг с пульс-линией) и текст:
- **`FitFlow`** — название;
- под ним строка даты `#date-label`: «день недели» (`#date-weekday`) и «число, месяц, год»
  (`#date-month`), например «понедельник, 10 авг. 2026 г.».

Справа три круглые кнопки (в порядке слева направо):
1. **Профиль** `#profile-switcher` (иконка человечка, title «Текущий профиль: …») —
   открывает диалог «Профили на устройстве» (`#profiles-dialog`, см. §7).
2. **✨ ИИ и быстрый ввод** `#ai-center-open` — открывает экран «Помощник FitFlow»
   (`#ai-view`, см. §8).
3. **🌞/🌙 Тема** `#theme-toggle` — быстрый переключатель светлая/тёмная (циклически,
   независимо от выбора «Авто/Светлая/Тёмная» в настройках).

## 2. Экран «Главная» (`#home-view`)

### 2.1. Приветствие (`section.greeting`)
- Заголовок `#greeting-title` по времени суток: «Доброе утро!» (05–12), «Добрый день!»
  (12–18), «Добрый вечер!» (18–23), «Доброй ночи!» (23–05). Если у активного профиля
  задано имя (не «Мой профиль»), оно вставляется в строку: «Добрый день, Вячеслав!».
- Подзаголовок `#greeting-sub` — мотивирующая фраза дня из массива
  `GREETING_SUBTITLES` (выбирается по номеру дня года, одинакова в течение дня),
  например: «Маленькие шаги каждый день важнее идеального понедельника».

### 2.2. Пилюли быстрого перехода (`#home-quicknav`)
Под приветствием — прилипающая полоса чипов-пилюль для прыжков к карточкам Главной.
Состав зависит от того, какие карточки видимы: **«День»** (к «Плану дня»/«Самочувствию»),
**«Вода»**, **«Питание»**, **«Вес»** — каждая с мини-иконкой. Тап плавно прокручивает
к карточке; активная пилюля подсвечивается по мере прокрутки (функции
`renderHomeQuickNav` / `updateHomeQuickNavActive`). Если карточек нет, полоса скрыта.

### 2.3. Карточка «План дня» (`#day-plan-card`)
Видна, если включён чек-лист дня, ИЛИ игровой режим, ИЛИ есть активный курс приёмов
(`isHomeCardFeatureEnabled`). Собирается динамически (`renderDayPlan`):
- **Чек-лист** (если включён в Настройки → Общее): строки с авто-отметками по записям —
  «Вода» («цель достигнута» / «1 250 из 2 500 мл»), «Еда» («основной рацион учтён» /
  «в процессе (2 приёма · 5 позиций)» / «ничего не добавлено»), «Активность»
  («отмечена» / «сегодня без активности»). Галочка ставится только при ПОЛНОМ
  выполнении плана (единый критерий с заданиями игрового режима).
- **Пункт «Сон»** (если включён чек-ин сна): «7 ч 30 мин · оценка 4/5» или
  «не отмечен — оценить»; маркер — эмодзи вашей оценки (🙂 и 🚀 — зелёные, 😐 — нейтральный,
  🙁/😫 — янтарные). Тап по строке открывает диалог чек-ина сна.
- **Задания дня** (если игровой режим): три карточки с прогрессом — вода до нормы,
  «Завтрак, обед и ужин» (3 приёма), 30 минут активности; отмечаются сами по записям.
  Рядом кнопка «🏅 Медали» → экран медалей (`#game-medals-view`).
- **Строки курса** (если есть курсы): название и кнопки-отметки каждого приёма
  («08:00 ✓»), ставятся вручную.

### 2.4. Карточка «Самочувствие» (`#day-mood-card`)
Видна при включённом чек-листе дня. С 0.5.6 — компактная плашка в ДВЕ строки
(`renderDayMoodCard`):
- верхняя строка: «🌗 Самочувствие» слева, справа — ряд из пяти смайл-кнопок
  😞 🙁 😐 🙂 😄 (1 тап = оценка дня записана, активная подсвечена рамкой);
- вторая строка во всю ширину — примечание: до оценки утром/днём «итоги — ближе
  к вечеру», после 17:00 «как прошёл день?», после оценки — «🙂 4/5 · хороший».
Оценка складывается в статистику (блок в «Статистике») и в синхронизацию дня.

### 2.5. Карточка «Вода» (`#water-card`)
- Заголовок: иконка капли, «Вода», подзаголовок «Визуальный прогресс за день»;
  справа кнопка микрофона `#water-voice-btn` (надиктовать воду голосом).
- **Кольцо прогресса** (SVG): в центре — выпито `#water-total` + «мл», под ним
  `#water-status` («из 2 500 мл» / при 100% — «Цель достигнута! 🎉»). Дуга заполняется
  градиентом.
- Кнопки-чипы: **«🥛 +250 мл»**, **«+500 мл»** (иконка бутылки), **«Своя мл»**
  (разворачивает строку `#water-custom-row`: поле объёма с крестиком-очисткой
  `#water-custom-clear`, «Добавить», «Отмена»), **«↺ Отмена»** `#water-undo`
  (красная: отменяет последнее добавление воды).
- Строка цели: «Дневная цель» + чип **«Цель»** → степпер «− 2500 мл +» (шаг 250 мл,
  `water-goal-minus/plus`).

### 2.6. Карточка «Питание» (`#food-card`)
- Заголовок: иконка прибора-вилки, «Питание», подзаголовок «Дневник питания и БЖУ»;
  справа **🏷️** `#custom-food-open` (диалог «Мои продукты») и микрофон `#food-voice-btn`.
- **Сводка калорий**: «0 / 2 000 ккал» (`#food-total` / `#food-goal-label`),
  прогресс-бар `#food-progress-fill`, статус-подсказка `#food-status`
  (например, «Добавьте приём пищи, чтобы начать»), строка БЖУ `#food-macros`.
- **Форма**: поле `#food-input` с плейсхолдером «Например: гречка 100г» и крестиком
  очистки; под ним кнопка **«Добавить»** `#food-add` на всю ширину (разбор фразы
  парсером FOOD_DB 960+ позиций; при неясности — ошибка в `#food-error`).
- **Ряд быстрых записей** `.quick-entry-row`: две тематические иконки —
  **⭐** `#quick-records-open` (диалог «Быстрые записи», вкладка «⭐ Комбо» с быстрым созданием),
  **🍽** `#quick-open-meals` (тот же диалог, вкладка «🍽 Мои блюда» с шаблонами и добавлением) —
  и кружок **«?»** (`data-help="quick-records"`) со справкой о возможностях быстрых записей.
- **Тип приёма пищи**: строка-сводка «Приём пищи: —» (`#meal-type-current`) + «Изменить»
  → развёрнутый список чипов `#meal-type-picker` (Завтрак/Обед/Полдник/Ужин/
  Поздний перекус + свои типы) и «＋ Свой тип» (`#custom-meal-type-toggle` с полем
  и «Сохранить»). По умолчанию тип выбирается по времени суток (Завтрак 06:00–12:59,
  Обед 13:00–15:59, Полдник 16:00–17:59, Ужин 18:00+).
- **Список записей дня** `#food-list`: у каждой — название, ккал, время; действия —
  изменить ✏️ (диалог `#food-edit-dialog`), удалить (со снэкбаром отмены, §6).
- Строка цели: «Цель по калориям» + чип **«Цель»** → степпер «− 2 000 ккал +» (шаг 100).

### 2.7. Карточка «Вес» (`#weight-card`)
Заголовок «Вес» («Текущий вес и динамика профиля»); тело: текущий вес
`#home-weight-current` и тренд `#home-weight-trend` («Записей веса пока нет», «−0,4 кг
за неделю» и т.п.); кнопка **«Записать»** `#weight-quick-open` → диалог «Записать вес»
(§7); внизу «График и история веса →» — переход в подробный вид веса.

### 2.8. Плашка приватности
Внизу Главной, с иконкой щита: «Все данные хранятся локально на устройстве.
Регистрация не требуется.»

## 4. Экран «Активность» (`#training-view`)

- Сводка: «Сегодня» + `#training-total` («Сегодня активности пока нет» / «45 мин»).

  - сворачиваемый блок «Готовые варианты активности» (`#activity-templates`) —

  - «Вид активности» — 8 кнопок: 🚶 Прогулка / 🏃 Кардио-бег / 🏊 Плавание /
    🚲 Велосипед / 🏋️ Силовая / 🧘 Растяжка / ⛸️ Активный отдых / 💪 Другое;
  - «Интенсивность» — чипы Лёгкая/Средняя/Высокая; под ними живая подсказка
    `#activity-kcal-hint` (оценка ккал по MET × вес × время);
  - «Длительность» `#workout-duration` + кнопка единиц «мин▾/ч▾»
    (`#workout-duration-unit` → диалог `#duration-unit-dialog`);
  - «Дата» `#workout-date` (по умолчанию сегодня, не позже сегодня);
  - сворачиваемый блок «Дополнительно: заметка и готовый вариант»
    (заметка 120 зн.; галочка «Одновременно сохранить как готовый вариант» + имя);
  - кнопка **«Сохранить активность»**.
- Список записей `#training-list`: вид, минуты, дата, заметка; изменить ✏️
  (`#workout-edit-dialog`, можно перенести на другую дату) и удалить (с отменой).
- FAB «↓ К форме» `#activity-fab` — появляется при прокрутке вниз, вертит обратно к форме.

### 4.1. Подсказка тренировок с часов (`#watch-workouts-suggest`)

- Показывается над формой, когда в Health Connect за сегодня есть сессии тренировок
  (ExerciseSessionRecord), которых ещё нет в дневнике.
- Заголовок: «⌚ Нашли тренировки с часов — добавить в дневник?». Для каждой сессии —
  строка с иконкой вида активности, названием, «длительность · время начала · с часов»
  и подписью «тип можно изменить после добавления», ниже кнопки **«Добавить»** /
  **«Игнорировать»**.
- «Добавить» создаёт запись активности (тип определяется по типу сессии и заголовку:
  бег→Кардио, велосипед→Велосипед, ходьба→Прогулка, силовая/тренировка→Силовая и т.д.),
  длительность из сессии, пометка «с часов (импорт)». «Игнорировать» скрывает подсказку
  (сессия не предлагается повторно).

### 4.2. Дневник силовых (`#strength-diary`) — вес × повторы

- Сворачиваемый блок **«🏋️ Силовая: вес × повторы»** — детальный журнал зала.
- Поля: «Название (необязательно)» и «Длительность, мин (в недельную цель)».
- Для каждого упражнения — набор подходов «Вес, кг × Повторы» (+/− подход, ✕ удалить
  упражнение); под названием живой расчёт: «тоннаж N кг · 1RM ≈ M кг» (тоннаж = Σ вес×повторы,
  1RM — среднее формул Эпли и Бржицки).
- Кнопки **«＋ Добавить упражнение»** (диалог `#strength-exercise-dialog`: чипы групп
  Грудь/Спина/Ноги/Плечи/Руки/Пресс/Кардио + список упражнений + поле «Своё упражнение»)
  и **«Сохранить силовую»**.
- При сохранении: если указана длительность ≥ 5 мин — в дневник активности добавляется
  запись «Силовая» (идёт в недельную цель и в оценку ккал по MET); без длительности —
  только журнал подходов. Ниже показывается «Сегодня сохранено».

### 4.3. Прогресс силовых (`#strength-history`)

- Сворачиваемый блок **«📈 Прогресс силовых»**:
  - «Личные рекорды по упражнениям» — лучший расчётный 1RM, лучший подход (вес × повторы)
    и дата последнего обновления по каждому упражнению;
  - «Прошедшие тренировки» — список сессий по датам (название, число упражнений, тоннаж,
    длительность). Данные — на устройстве, входят в резервную копию.

## 5. Экран «Настройки» (`#settings-view`) и подразделы

Шапка карточки: «Настройки» — «Оформление Главной и разделы приложения».
Под ней контекст профиля (`#profile-settings-context`): «Имя профиля» и пояснение
«Вес, цели, история и уведомления относятся к этому профилю.»

Меню разделов (каждая строка: эмодзи, название, пояснение, «?»-справка, шеврон):
1. **⚙️ Общее** — «Тема, чек-лист, карточки Главной, игровой режим».
2. **👤 Профиль и цели** — «Пол, возраст, рост, активность, расчёт норм».
3. **🔔 Уведомления** — «Мотивация, приёмы пищи, вода и вечерняя активность».
4. **💊 Мой курс** — «Витамины, добавки и приёмы по расписанию с напоминаниями».
5. **✨ Помощник FitFlow** — «Офлайн-анализ, облачная нейросеть или модель на устройстве».
6. **💾 Данные и резервные копии** — «Экспорт, импорт, сброс».
7. **ℹ️ О приложении** — «Версия, источники данных, методика, условия».

### 7.5. «Методика расчётов» (`#methodology-dialog`)
- **Заголовок:** «Методика расчётов»
- **Текст пунктов:**
  - *Как FitFlow понимает фразы.* Текст разбирается по правилам и словарям прямо на телефоне, без интернета: сначала находится количество («150 г», «2 шт», «250 мл»), затем название продукта сопоставляется со встроенной базой из 960+ позиций, а из неё берутся калории и БЖУ на 100 г и пересчитываются на вашу порцию.
  - *Откуда значения.* База продуктов собрана из открытых научных источников (USDA FoodData Central, Open Food Facts). Это усреднённые справочные данные: у конкретного бренда, сорта или рецепта значения могут отличаться — поэтому важные приёмы пищи лучше перепроверять по упаковке.
  - *Средняя калорийность и объёмы по умолчанию.* Калорийность блюд в базе — усреднённая: у одного и того же блюда рецепты отличаются (суп может быть овощным, а может — с мясом и макаронами), поэтому расчёт показывает честную среднюю оценку, а не точный лабораторный состав именно вашей порции. Это не упрощение FitFlow, а реальность открытых научных баз. Если у вас есть точные данные с упаковки — внесите продукт в «Мои продукты» (кнопка 🏷 в разделе Питание): ваши значения перекроют усреднённые. То же с объёмами без точного указания: «тарелка» считается как ≈250 г, «стакан» — 250 мл, «чашка» — 200 мл, «порция» — 200 г, «кусок» хлеба — 40 г, а еда совсем без количества — осторожные «≈ 100 г». Хотите максимальную точность — укажите вес или рецепт вручную (граммы честнее любых средних).
  - *Активность и калории.* Энергозатраты считаются по методу MET (метаболический эквивалент вида активности): ккал ≈ MET × вес (кг) × длительность (часы). Метод международный, но даёт оценку «в среднем» — реальный расход зависит от возраста, пола и интенсивности.
  - *Личные нормы воды и калорий.* Вода — ориентир ~30 мл на кг веса с надбавкой при высокой активности. Калории — формула Миффлина — Сан Жеора (пол, возраст, рост, вес) с поправкой на среднюю активность; если данные не заполнены, используется упрощённая оценка по весу. Расчёт выполняется на устройстве в Настройках → «Профиль и цели».
  - *Цели по умолчанию.* Вода — 2500 мл, калории — 2000 ккал в день: это общие бытовые ориентиры, а не врачебная рекомендация. Свою норму лучше уточнить у специалиста и задать в профиле.
  - *Встроенный анализ.* Разделы «Анализ», «Рецепт» и «Спросить» работают офлайн: по правилам, словарям и вашим записям — без отправки данных куда-либо. Рецепт собирается из реально перечисленных продуктов, ответы — по тематическим правилам и базе 960+ продуктов; при малом числе записей выводы честно помечаются как общие.
  - *Характер данных.* Все показатели FitFlow — справочные, а не медицинские: приложение помогает вести учёт и видеть картину, но не заменяет врача.
- **Кнопка:** «Понятно» (`#methodology-dialog-ok`).

## 9. Экран «Настроить уведомления» (`#notifications-view`)

Открывается из Настройки → Уведомления и из кнопки «⚙️ Настроить» в самих уведомлениях

(с вендорской подсказкой `#setup-vendor-note`: Xiaomi/MIUI и др.). Блок «Проверить

Типы напоминаний: вода (сетка интервалов 08:00–22:00; заголовок «💧 Время выпить
воду», короткий текст «Сегодня: X из Y мл» — с 0.5.7 целиком виден в свёрнутом виде;
кнопки действия «+ 250 мл воды» и «⚙️ Настроить» в нативном канале), приёмы пищи,
утренняя мотивация, вечерняя активность, приёмы курса. Правила «вежливости»: смахнутое напоминание о воде молчит
≥45 минут; **с 0.5.6 — если вода записана, ближайшее напоминание пропускается
автоматически** (порог = интервал сетки; сетка не сдвигается). Тап по уведомлению
ведёт в нужный раздел; «⚙️ Настроить» — прямо в соответствующий блок настроек
с тройной подсветкой (`.settings-flash`).

## 11. Данные, хранилище SQLite и резервные копии

- **Движок базы данных SQLite (с 0.6.0)**:
  - Реляционная база данных SQLite (`sql.js` 1.14.1 на базе WebAssembly) с сохранением бинарного файла базы в `IndexedDB` (`fitflow_sqlite_db`).
  - **Таблицы**: `meta`, `profiles`, `states`, `daily_summaries`, `food_entries`, `workout_entries`, `weight_entries`, `custom_foods`, `combos`.
  - **Двойная запись (Dual-Write)**: каждый `saveState()` сохраняет состояние в `localStorage` и асинхронно синхронизирует реляционные таблицы SQLite.
  - **Надёжность и откат**: перед первой миграцией создаётся резервный JSON-снимок `fitflow:pre-sqlite-backup`; при любой ошибке WASM приложение автоматически и без потери данных использует `localStorage`.
- Состояние профиля — `localStorage`-ключ `fitflow:state:<profileId>` (вода, еда,
  активность, вес-история, цели, настройки, чек-лист, игровой режим, сон, курсы,
  свои продукты/блюда/комбо/приёмы пищи).
- Служебные ключи: `fitflow:terms-accepted-v1`, `fitflow:onboarding-done`,
  `fitflow:setup-wizard-done`, `fitflow:pro`, `fitflow:support-next`, `fitflow:pre-sqlite-backup`, журнал разборов и др.
- Экспорт — один JSON со scope `all-profiles`: все профили, их история, цели и
  настройки (включая тему/шрифты/уведомления и PRO-статус). BYOK-ключи облачного ИИ
  в копию НЕ входят (приватность; решение владельца). Импорт all-profiles заменяет
  профили после подтверждения; импорт одного профиля — объединяет записи.
- Тестовая PRO-пара для проверки: `test@mail.ru` + код из `tools/make-pro-code.js`.
