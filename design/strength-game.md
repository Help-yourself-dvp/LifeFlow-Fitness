# Геймификация силовых — проектирование (0.8.6)

> Идея владельца: медали/награды за личные рекорды в силовых, НЕ «каждые 100 г»,
> а по лестнице порогов, своей для каждого упражнения. На старте шаги крупные
> (брать легко), дальше шаг сжимается, в конце «каждый кг — приз».
> Здесь — детальная логика. Код — чистые функции в `app.js` (тестируются).

---

## 1. Модель: «лестница уровней» на упражнение

У каждого упражнения есть **база** (первый порог) и **расписание шагов** — список
приростов. Уровень = число пройденных порогов. Пороги считаются накопительно:

```
порог(0) = база
порог(k) = порог(k−1) + шаг[k−1]   (после исчерпания списка шаг повторяется последним)
```

Так получается именно то, что просили: **сначала +5/+10 кг за награду, потом +3,
в конце +1 за каждый приз.**

Пример — жим лёжа (база 40, шаги 5,5,5,5,3,3,3,1,1,…):

```
40, 45, 50, 55, 60, 63, 66, 69, 70, 71, 72, … 99, 100, 101, …
└ 5 кг ────────────┘  └ 3 кг ────┘  └ 1 кг (каждый кг — приз) ──┘
```

## 2. Почему пороги разные у упражнений

Разные движения живут в разных диапазонах рабочих весов. Опорные нормативы
(для мужчины ~80 кг; из открытых таблиц strength standards):

| Упражнение | Новичок | Средний | Продвинутый | Элита |
|---|---|---|---|---|
| Жим лёжа | 40 | 80 | 120 | 160 |
| Приседания | 60 | 120 | 180 | 220 |
| Становая | 80 | 160 | 200 | 240 |
| Жим стоя | 27.5 | 65 | 87.5 | 112.5 |

Наши пороги — **прикидочные для прогрессии**, а не официальные нормативы:
их цель — дать достижимую следующую цель, а не ранжировать пользователя.

## 3. Лестницы (таблица)

| Упражнение (по ключам) | База, кг | Шаги, кг |
|---|---|---|
| Жим лёжа (штанга/гантели/наклонная) | 40 | 5,5,5,5, 3,3,3, 1… |
| Приседания (со штангой, фронтальные) | 60 | 10,10,10, 5,5,5, 1… |
| Становая тяга | 70 | 10,10,10, 5,5,5, 1… |
| Жим стоя / армейский жим / жим гантелей сидя | 30 | 5,5, 3,3, 1… |
| Тяги (штанга в наклоне, гантель, верхний блок, к подбородку) | 30 | 5,5, 3,3, 1… |
| Жим ногами | 100 | 10,10,10, 5,5, 1… |
| **Всё остальное (generic)** | 20 | 5,5, 3,3, 1… |

Ключи матчатся подстрокой по названию упражнения (регистр/ё не важны). Упражнение,
не попавшее в таблицу, берёт generic-лестницу — награды не исчезают, просто пороги
«нейтральные».

## 4. Расчёт уровня

```
PR = лучший расчётный 1RM упражнения по всем сессиям (computeExercise1RM)
level = сколько порогов ≤ PR
nextTarget = первый порог > PR
nextDelta = nextTarget − PR   (сколько осталось до следующего уровня)
```

Всё — чистые функции: `strengthLadderFor(name)`, `strengthTargetAt(ladder, level)`,
`computeStrengthLevel(name, pr)`. Покрыто node-тестами.

## 5. Где это проявляется в интерфейсе

1. **Прогресс силовых** (`#strength-history`): под каждым рекордом — строка
   «🏅 цель: 101 кг (+1 кг)» и метка уровня «· Lv N».
2. **Экран «Медали»** → новая группа «🏋️ Сила (уровни)»: одна карточка на упражнение
   (до 8 самых сильных): уровень, 1RM, следующая цель. Заработанная — золотая,
   в процессе — с прогресс-баром до следующего порога.
3. **Момент награды**: при сохранении силовой, если у упражнения поднялся уровень, —
   тост «🏅 Новый уровень: <упражнение> Lv N».

## 6. Что сознательно НЕ делаем (анти-перегруз)

- Нет медали на «каждые 100 г/кг» — только лестницы с шагами.
- Нет отдельной медали на каждый порог — одна карточка на упражнение, уровень
  растёт внутри (иначе экран медалей завалило бы сотнями плиток).
- Нет нормативных «рангов» по весу тела (новичок/элита) — это отдельная, более
  тонкая шкала; добавим только по прямому запросу.
- Нет рейтинга/лидербордов — приложение локальное, «соревнование» только с собой.

## 7. Игровая логика в других местах (что уже есть + идеи)

Уже работает: задания дня (вода/3 приёма/30 мин), медали привычек, бега, шагов,
снижения веса, «серии» дней. Силовые уровни дополняют этот ряд.

Кандидаты «потом» (не сейчас, чтобы не перегрузить):
- **Серия тренировок** (N силовых за месяц) — аналог «серии дней».
- **Тоннаж-рекорд дня/недели** — «самый объёмный день».

## 8. ИИ-рекомендации по тренировкам (P33, не навязчиво)

Цель владельца: приложение делает многое само, подсказывает, но не навязывает.

Дизайн (зафиксирован в POSTPONED P33):
- Только **детерминированные** правила сначала: смотрим прогресс (1RM растёт/стоит),
  перерывы между сессиями (дни), равномерность нагрузки (все ли группы покрыты) —
  и выводим 1–2 коротких совета («жим лёжа не растёт 3 недели — попробуйте +1 повтор
  вместо +2.5 кг», «ноги без нагрузки 6 дней — стоит добавить присед»).
- ИИ-текст — опциональный слой поверх фактов (встроенный анализ / нейросеть на
  устройстве), только по явному открытию «Анализ», никогда не пишет сам в дневник.
- Никаких пушей/плашек-назойливостей: советы живут в разделе «Прогресс силовых»
  и в анализе, не всплывают сами.
