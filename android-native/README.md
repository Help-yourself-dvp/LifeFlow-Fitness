# android-native/ — нативные исходники Android

Здесь лежит нативный код приложения (Java/Kotlin). При сборке шаг
**«Копировать нативные исходники (android-native/)»** в `build.yml` копирует
эти файлы в `android/app/src/main/java/com/fitflow/app/`.

## Файлы

| Файл | Назначение |
|---|---|
| `MainActivity.java` | Точка входа, мост JS↔Android: будильники, батарея, сохранение бэкапа, распознавание речи |
| `FitFlowWidgetProvider.java` | Виджет на рабочем столе (вода, шаги, кнопка +250) |
| `WaterReminderReceiver.java` | Напоминания о воде: канал, расписание, пауза, кнопки в уведомлении |
| `HealthSyncReceiver.java` | Периодическая фоновая синхронизация с Health Connect |
| `HealthConnectHelper.kt` | Чтение шагов, сна, тренировок, веса и роста; запись тренировок |

## Как править

Обычным способом — отредактировать файл и запушить. Сборка запустится сама.
**Ручная замена `build.yml` для этого больше не нужна.**

## История

До версии 0.8.27 весь этот код был вписан внутрь `.github/workflows/build.yml`
как heredoc-блоки, из-за чего файл занимал 2251 строку, а каждая правка натива
требовала ручной замены workflow владельцем (GitHub App не может пушить
в `.github/workflows/`). В 0.8.27 код вынесен сюда без единого изменения —
извлечение проверено побайтовым сравнением.

## Важно

- Пакет во всех файлах — `com.fitflow.app`. При переименовании пакета
  поменять и `package`-строку, и путь `DEST` в workflow.
- Список копируемых файлов задан в workflow явно. **Добавили новый файл —
  впишите его в этот список**, иначе он не попадёт в сборку.
- Автотест `test-ui-init.js` читает workflow вместе с этим каталогом
  (функция `readBuildBundle`), поэтому проверки нативного кода продолжают работать.
