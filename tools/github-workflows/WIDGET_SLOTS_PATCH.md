# Патч разметки виджета для build.yml (0.9.4)

> **СТАТУС: ГОТОВ, ЖДЁТ ВСТАВКИ ⏳** — правка нужна, чтобы сборка 0.9.4
> собралась. Без неё компиляция упадёт: `FitFlowWidgetProvider.java` из
> `android-native/` ссылается на новые id (`widget_slot_1…10`), которых в
> старой разметке нет.

**Зачем.** До 0.9.4 строки виджета были зашиты в разметку намертво:
`widget_water`, `widget_food`, `widget_steps` — по вьюхе на показатель.
Пользователь просил выбирать состав виджета галочками, а в такую схему выбор
не встраивается: пришлось бы держать отдельную вьюху под каждый из восьми
показателей и в каждой из двух раскладок.

**Что делает патч.** Заменяет две захардкоженные разметки на генератор
универсальных слотов. Слот — это контейнер `widget_slot_N` (скрытый по
умолчанию) с текстовой строкой `widget_slot_N_text` и двумя заранее
покрашенными полосами прогресса: `_bar` (бирюзовая, вода) и `_bar2` (янтарная,
питание). Java заполняет столько слотов, сколько показателей выбрал
пользователь, остальные прячет. Компактная раскладка — 5 слотов, большая — 10.

Две полосы вместо одной перекрашиваемой — сознательно: у `setProgressTintList`
нет перегрузки с `int`, и вызов через `RemoteViews.setInt` упал бы уже на
устройстве («Ошибка загрузки виджета»), а не на сборке.

## Как применить (2 шага)

1. Открыть на телефоне: <https://github.com/Help-yourself-dvp/LifeFlow-Fitness/edit/arena/01a02da3-lifeflow-fitness/.github/workflows/build.yml>
2. Заменить содержимое файла целиком на актуальное зеркало и нажать «Commit changes»:
   <https://raw.githubusercontent.com/Help-yourself-dvp/LifeFlow-Fitness/arena/01a02da3-lifeflow-fitness/tools/github-workflows/build.yml>

Зеркало `tools/github-workflows/build.yml` уже содержит эту правку — оно и есть
эталон. Ничего дописывать руками не нужно.

## Что именно изменилось в файле

Шаг `Patch manifest and icons`, блок между `layout = res / 'layout'` и
`xml = res / 'xml'` (в прежней версии — строки 392–427). Вместо двух вызовов
`write_text` с полным XML появились две функции и два коротких вызова:

```python
          def widget_slot(i, text_size, bar_height, gap):
              ...  # контейнер + текст + две полосы прогресса

          def widget_layout_xml(slots, padding, title_size, profile_size,
                                text_size, bar_height, gap, btn_height, btn_text):
              ...  # шапка, слоты 1..N, подсказка widget_empty, две кнопки

          (layout / 'fitflow_widget.xml').write_text(
              widget_layout_xml(5, 14, 11, 10, 13, 4, 4, 34, 11), encoding='utf-8')
          (layout / 'fitflow_widget_large.xml').write_text(
              widget_layout_xml(10, 16, 12, 11, 15, 5, 5, 38, 12), encoding='utf-8')
```

Сохранены без изменений: `widget_root`, `widget_profile`, `widget_water_btn`,
`widget_record_btn` — на них завязаны нажатия виджета (открыть приложение,
+250 мл, «Записать»). Добавлен `widget_empty` — подсказка на случай, когда
пользователь снял все галочки.

## Проверки, которые уже выполнены

- Python-скрипт шага разбирается (`ast.parse`), обе раскладки — валидный XML
  (`xml.dom.minidom`): 25 id в компактной, 45 в большой.
- Каждый `R.id.widget_*`, к которому обращается Java, присутствует в разметке —
  это проверяет тест `0.9.4 все id из Java объявлены в разметке` в
  `test-ui-init.js` (прогоняется локально, падает при расхождении).
- Число слотов в раскладках сверено с бюджетами `WIDGET_SIZES` в `app.js`
  (3/5/8 строк при 5 и 10 слотах — запас есть).
