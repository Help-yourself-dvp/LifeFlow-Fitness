# Патч: клавиатура/IME (adjustResize + прогрев фокуса WebView)

> Статус: ✅ **ПРИМЕНЁН** (пользователь, 06.08.2026, коммиты a1c67a8/18ebda8
> «Update build.yml 0.3.17»; оба фрагмента на месте, зеркало tools/ синхронизировано).
> Ниже — историческая запись того, что именно применено.

## Зачем

Два симптома на устройстве (Honor Magic 8 Pro), которые **не удалось устранить
веб-кодом** (проверено в 0.3.13–0.3.17: убраны плавные скроллы, скролл-компаньон,
сам модальный диалог ИИ — симптомы идентичны):

1. После холодного старта первый тап по полю ввода клавиатуру не открывает
   (вторая попытка — открывает), а в «провальной» сессии молчит голосовой
   набор GBoard.
2. Открывшаяся клавиатура перекрывает поле ввода — страница не «поднимается».

Корень найден: в шаблонном `AndroidManifest.xml` Capacitor **нет
`android:windowSoftInputMode`**, а `configChanges` содержит `keyboard`.
Итоговый дефолтный режим не сжимает вьюпорт WebView при появлении клавиатуры
(поле перекрывается), и первая IME-сессия на части устройств теряется.

## Что вставить (2 небольших фрагмента)

### 1. Манифест — шаг «Patch manifest and icons»

Внутри python-блока, **перед** строкой `man.write_text(t, encoding='utf-8')`
(например, сразу после блоков `water_receiver`), добавить:

```python
          # IME/клавиатура (0.3.17): без softInputMode система не сжимает вьюпорт
          # WebView — клавиатура перекрывает поле, а первая IME-сессия после
          # холодного старта теряется. adjustResize: WebView сам сжимается,
          # Chromium скроллит к полю ввода.
          if 'windowSoftInputMode' not in t:
              t = t.replace('android:name=".MainActivity"',
                            'android:name=".MainActivity"\n            android:windowSoftInputMode="adjustResize"', 1)
```

### 2. MainActivity — шаг «Patch MainActivity …»

В heredoc'е `MainActivity.java`, в `onCreate` **сразу после строки**
`super.onCreate(savedInstanceState);` добавить:

```java
                // IME «прогрев» (0.3.17): у части WebView первая сессия клавиатуры
                // после холодного старта теряется, если у корневого WebView ещё
                // не запрашивали фокус. requestFocus() после загрузки страницы
                // лечит «клавиатуру со второго тапа» и молчащий набор GBoard.
                try {
                    final WebView wv = getBridge() != null ? getBridge().getWebView() : null;
                    if (wv != null) {
                        wv.postDelayed(new Runnable() {
                            @Override public void run() { wv.requestFocus(); }
                        }, 500);
                    }
                } catch (Exception e) { }
```

## Ожидаемый эффект и откат

- Поле ввода больше не перекрывается: система сжимает WebView, Chromium сам
  прокручивает к сфокусированному полю. Нижняя навигация при открытой клавиатуре
  может «подпрыгивать» над ней — это нормальное поведение adjustResize.
- Первый тап после холодного старта должен открывать клавиатуру сразу, а микрофон
  GBoard — слышать диктовку (проверка сценария «холодный старт → раздел ИИ →
  тап в поле» — за пользователем).
- Данные приложения не затрагиваются. Откат — удалить оба фрагмента.
