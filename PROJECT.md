# 1. Назначение проекта

FitFlow — мобильное Android-приложение (фитнес-трекер) на базе Capacitor/WebView.
Работает полностью локально: без сервера, без регистрации, без обязательного
интернета. Все данные хранятся только на устройстве пользователя.

В репозитории задуман второй продукт — LifeOps (помощник: напоминания, погода,
вещи); он не разрабатывается, пока живёт FitFlow.

# 2. Статус и основные возможности

### ✔ Работает офлайн и бесплатно
- **Вода**: кольцо прогресса, быстрые кнопки, цель, напоминания 60/90/120 мин с
  кнопкой «+250 мл» прямо в уведомлении, та же кнопка на виджете и голосом.
- **Питание**: умный текстовый парсер + локальная база 1000+ продуктов (ккал и
  БЖУ на 100 г / на штуку, аудит в `test-food-db.js`), свои и избранные блюда,
  приёмы пищи, голосовой ввод, штрихкод-сканер (ZXing, 0.9.2) с запросом состава
  в Open Food Facts под флагом `onlineFeatures.barcodeLookup` и кэшем.
- **Активность и вес**: журнал (прогулки/спорт/отдых), шаблоны, MET-оценка
  энерготрат; история веса и графики 7/30/всё время.
- **Шаги и сон с часов**: Android Health Connect (Zepp/Amazfit/Garmin/Samsung) +
  аппаратный шагомер телефона, трёхуровневый приоритет источников без задвоения.
- **Силовой дневник**: каталог упражнений и свои, подходы «вес × повторения»,
  тоннаж и разовый максимум (Эпли/Бржицки), прогресс по упражнению, уровни силы,
  шаблоны и план по дням, таймер отдыха, экспорт в Health Connect.
- **Профили и копии**: до 10 локальных профилей, экспорт/импорт `all-profiles`;
  резервная копия не содержит секретов (`stripSecretsForBackup`, 0.9.45).
- **Виджеты**: «FitFlow · список» (настраиваемые строки), «бенто», «кольца»
  (тёмный/светлый), «плитки» (тёмный/светлый). Виджет «капля» удалён в 0.9.47.
- **ИИ-центр**: вкладки «Ввод» (текст/диктовка/фото-заметка), «Рецепт»,
  «Анализ», «Спросить». «Встроенный анализ» считает детерминированно, без сети.
- **Нейросеть на устройстве** (0.4.x): плагин `plugins/fitflow-local-ai`
  (Kotlin + LiteRT-LM) импортирует Gemma `.litertlm`, отвечает стримингом;
  зрячие модели распознают фото еды. Цифры считает не модель, а локальные
  алгоритмы — модели запрещено считать.
- **Облачный BYOK-ИИ** (опционально, выключен по умолчанию): Gemini, DeepSeek,
  OpenRouter, GigaChat. Ключ хранится только на устройстве.

### ⏳ В разработке / отложено
- Стратегия — нейросеть на устройстве; облако сводится к нулю по решению
  пользователя. Дорожная карта — `ROADMAP.md`, отложенное — `POSTPONED.md`.

### ✖ Не реализовано (принципиально)
- Облачные серверные бэкенды и платная регистрация (offline-first / BYOK).

# 2.9. Карта контуров (офлайн-first)

**Контур А — офлайн-ядро.** Всё вышеперечисленное работает без сети; данные не
покидают телефон, кроме явного экспорта копии пользователем.

**Контур Б — опциональный онлайн (выключен по умолчанию).** Каждый запрос в
сеть — по видимому действию и с пометкой «онлайн»; ядро от выключения контура не
зависит. Сейчас: облачный BYOK-ИИ и штрихкод-поиск в Open Food Facts. Ключ и
включение — только руками пользователя.

---

# 3. Архитектура

```
index.html → style.css → app.js → Capacitor → Android WebView → APK
```

Логика в отдельном `app.js`; нативный код — в `android-native/` (копируется в
сборку циклом), плагины — в `plugins/`. Сборка читает номер версии из
`version.txt`, поэтому смена версии — коммит этого файла, а не правка workflow.

---

# 4. Технологии

- HTML / CSS / Vanilla JS (без фреймворков); Material 3 (`--md-sys-color-*`).
- Хранение: **SQLite** (sql.js WebAssembly в IndexedDB) + **localStorage** как
  постоянный Dual-Write-резерв и источник первой миграции (снимок
  `fitflow:pre-sqlite-backup` пишется до переноса). Оба хранилища нужны намеренно.
- Capacitor 5 + `@capacitor/local-notifications`; мост `FitFlowExport`
  (JavascriptInterface): резервные копии (SAF), статус уведомлений/батареи,
  открытие системных экранов, `scanBarcode`, `openExternalUrl`.
- Шрифты виджетов — локальные `assets/fonts/manrope-*.ttf` (offline-first).
- Сборка — GitHub Actions; владелец сам подменяет активный
  `.github/workflows/build.yml` по зеркалу `tools/github-workflows/build.yml`
  (пуш в `.github/` агенту запрещён).

# 6. Основные файлы

# 7. Принципы

- Простая архитектура; без сервера и регистрации; данные только локально.
- Совместимость поверх старых версий без потери данных пользователя.
- Гард не-нагромождения: новые функции — внутри существующих механизмов или за
  выключенным флагом; никаких видимых заглушек и ложных аффордансов.
- Правдивость расчётов — приоритет №1: считают детерминированные алгоритмы;
  нейросеть объясняет, но не считает.
- «Не молчать»: нераспознанный ввод и неудачи объявляются явно, а не скрываются.

# 8. Хранение данных

«День» — локальная календарная дата устройства (не UTC-срез): записи не уезжают
в соседние сутки на границе полуночи и при смене пояса.

Ключи localStorage (резерв и миграция): `fitflow:state`, `fitflow:state:<id>`,
`fitflow:profiles`, `fitflow:theme`, служебные флаги (условия, онбординг), не
входящие в копию. Основная масса данных — в таблицах SQLite: `meta`, `profiles`,
`states`, `daily_summaries`, `food_entries`, `workout_entries`, `weight_entries`,
`custom_foods`, `combos`.

Управление профилями: в списке видны названия; тап переключает, стрелка
раскрывает параметры одного профиля. Экспорт — один JSON `all-profiles`
(полная ЗАМЕНА после предупреждения); старая одиночная копия — ОБЪЕДИНЕНИЕ.

---

# 9. Резервная копия

Экспорт — `fitflow-backup-ГГГГ-ММ-ДД.json` (в нативе — системное окно SAF).
Импорт через `<input type="file">`. С 0.9.45 из копии вычищаются секреты
(ключ облачного провайдера) функцией `stripSecretsForBackup` — копия
пересылается почтой/мессенджерами и не должна нести ключ.

---

# 10. Парсер продуктов

Фраза делится по запятым, «и», тире. В каждой части ищется количество
(число + единица: г/кг/мл/л/шт/ст.л/ч.л/стакан/чашка/порция), затем продукт
(самое длинное совпадение, границы слова + лёгкая морфология, нормализация
числительных и опечаток речи). Калории — ккал/100 г × вес или ккал × штук; без
количества — условная порция. Нераспознанное честно помечается. ИИ-разбор —
только опциональное дополнение, базовый путь офлайн.

# 11–12. Интерфейс и тема

Material 3; светлая — основная, тёмная — AMOLED. Системные `alert/confirm` не
используются — собственные диалоги в стиле приложения (в т.ч. подтверждение
очистки заполнения силовой и сброса данных). Тема: Авто/Светлая/Тёмная,
хранится в `fitflow:theme`.

# 13. Проверка работоспособности

```bash
npm run test:all   # test-parser.js + test-ui-init.js + test-food-db.js
```

# 16. Лицензионная чистота сторонних компонентов

Правило: любой новый сторонний компонент (модель, база, библиотека, шрифт)
вносится в этот раздел ДО включения в релиз; обязательства — в чек-лист 16.4.

## 16.1 Локальные нейросети (.litertlm)

| Модель | Лицензия | Обязательства |
|---|---|---|
| Gemma 4 E2B / Qwen3 | Apache 2.0 | Текст лицензии + attribution в экране «О приложении → Лицензии». Коммерция и магазины разрешены. |
| Gemma 3 / 3n | Gemma Terms of Use | Соблюдать Prohibited Use Policy; дисклеймер «не медицинский совет»; условия доводятся до пользователя. |

По умолчанию — Apache-модели (минимум обязательств); Gemma ToU — только после
экрана лицензий и дисклеймера.

## 16.2 Источники данных

- **USDA FoodData Central** — public domain; упоминание — хороший тон.
- **Open Food Facts** — ODbL: attribution обязателен (есть в «О приложении»);
  база пересобрана и хранится локально, наружу из APK не распространяется.
  Полный аудит базы — пункт стор-чеклиста перед первой публикацией.

## 16.3 Библиотеки, шрифты, иконки

- Capacitor и плагины — MIT/Apache-2.0; перед магазином вынести список версий в
  экран лицензий. Иконки — собственные SVG; эмодзи — системные. Шрифты виджетов —
  локальные файлы с проверенной лицензией (см. THIRD_PARTY.md).

## 16.4 Чек-лист перед первой публикацией в магазине

1. Экран «Лицензии третьих сторон»: Apache/MIT офлайн в assets; ODbL-атрибуция;
   при Gemma 3/3n — текст ToU + ссылка на Prohibited Use Policy.
2. Дисклеймер «ИИ-подсказки — не медицинский совет» в условиях и лицензиях.
3. В описании магазина — локальная обработка данных (offline-first).
4. При появлении монетизации/аналитики — новый проход по чек-листу.
