# 1. Назначение проекта

FitFlow — мобильное Android-приложение (фитнес-трекер) на базе Capacitor/WebView.

Состоит из двух частей, которые позже будут развиваться:

1. **FitFlow** — фитнес-трекер (вода, калории, тренировки) — разрабатывается сейчас.
2. **LifeOps** — универсальный помощник (напоминания, погода, хранение вещей) — планируется.

Приложение работает полностью локально.

Сервер отсутствует. Регистрация отсутствует. Интернет для работы не требуется.

Все данные хранятся только на устройстве пользователя.

# 2. Статус проекта и основные возможности

## Статус реализации функционала (что работает, что в разработке, что не реализовано)

### ✔ Реализовано на 100% (работает полностью офлайн и бесплатно)
- **Учёт воды**: прогресс-кольцо, быстрые кнопки, цель, настраиваемые напоминания (60/90/120 мин) **с кнопкой «+250 мл» прямо в уведомлении в шторке** (запись без открытия приложения, живое обновление текста уведомления и виджета, расписание переживает перезагрузку телефона), управление кнопкой «+250 мл» в фоне с Android-виджета, голосовое добавление через кнопку «🎤».
- **Учёт питания**: умный текстовый парсер и база на **925+ офлайн-продуктов**, расчёт БЖУ (белки, жиры, углеводы), пользовательские блюда, избранные блюда, приёмы пищи, голосовой ввод через кнопку «🎤» в форме.
- **Учёт активности и веса**: тренировки в часах/минутах, шаблоны активности, заметки, энерготраты по MET; история веса и графики динамики (7/30 дней/всё время).
- **Локальные профили и резервные копии**: до 10 профилей на одном устройстве с раздельными целями и весом; единый экспорт/импорт `all-profiles`.
- **Чек-лист дня на Главной**: визуальный контроль дня (вода, питание, активность) с синхронным обновлением при любых изменениях. Рядом — отдельная секция «🌗 Самочувствие за день» с оценкой всего дня по шкале 1–5 (😔😐😊), отмечать удобнее вечером.
- **Разворачиваемые секции в Настройках (аккордеон)**: компактный вид (заголовок + 1 строка статуса) при выключенном тумблере и раскрытие параметров при включении.
- **ИИ-центр (Вкладки и Локальный эксперт FitFlow)**:
  - Вкладки «⚡ Ввод» (текст, диктовка 🎤 и фото-заметка 📷 в одном месте — умный парсер распределяет воду, еду и активность по разделам), «🥑 Рецепт из холодильника» (с подтверждением продуктов под ваш профиль), «📊 Анализ недели / месяца» (также доступен карточкой на странице Статистики) и «💬 Вопрос нутрициологу» (text/голос). Поля ввода многострочные и растягиваются за уголок.
  - В режиме «Локальный эксперт FitFlow (0 ГБ)» система мгновенно генерирует рецепты, БЖУ и консультационные отчёты по статистике на основе встроенной базы 925+ продуктов и алгоритмов нутрициолога, с честным замером времени `performance.now()`.
- **Выбор локального файла нейросети (.gguf / .tflite / .bin) на устройстве**: через нативное системное окно выбора файлов Android (`Intent.ACTION_OPEN_DOCUMENT`) приложение считывает реальный путь, имя и размер выбранного файла на телефоне.

### ⏳ В разработке (следующие этапы архитектуры)
- **Нейросетевой инференс (выполнение моделей .gguf / .tflite на процессоре/NPU телефона внутри APK)**: сейчас файл модели успешно выбирается и считывается, однако само выполнение (генерация токенов для ответа на произвольные вопросы вроде «Столица России») требует встраивания C++ библиотеки Llama.cpp (`libllama.so`) или Google LiteRT / MediaPipe GenAI SDK (`com.google.mediapipe:tasks-genai`) в сборочный файл Gradle (`build.yml`).
- **Целевой сценарий «Фото еды» (подтверждён пользователем)**: снимок блюда → ИИ распознаёт продукты и их вес → JSON сопоставляется с локальной базой 925+ продуктов → калории и БЖУ записываются в дневник. Добавление еды тремя равноправными способами: текст, голос, фото. Аналогично «Рецепт из холодильника»: фото полки холодильника → список продуктов → несколько рецептов из них. До появления ИИ-модели вкладка «⚡ Ввод» (с 0.2.9 объединённая) честно работает в режиме «текст/голос + локальная база», фото хранится как заметка.
- **Миграция хранилища с localStorage на SQLite** для долговременного хранения истории за многие годы.

### ✖ Не реализовано (и отложено)
- Облачные серверные бэкенды и платная регистрация (мы принципиально развиваем Offline-first / BYOK подход без затрат для разработчика).
- Интеграция Android Health Connect (отложена до завершения работы над SQLite и ИИ-ядром).

### 🔮 Задокументированные будущие решения (обсуждены с пользователем 05–06.08.2026)
- **Облачный ИИ — только для тестов (решение 06.08.2026).** Требования к приложению подтверждены: FitFlow — offline-first, для его работы не нужны интернет, API-ключи и регистрация; стратегическая цель — нейросеть на устройстве (без VPN, ключей и облачных лимитов). Облачный BYOK-режим (Gemini/DeepSeek/OpenRouter), добавленный в 0.3.5, оставлен **только как временный тестовый стенд** сценариев будущего локального ИИ (свободные вопросы, фото-распознавание, живой текст рецептов/анализа) и в UI помечен «🧪 эксперимент». Облако не должно становиться обязательным ни для одной функции; при появлении нейросети на устройстве его доля сводится к нулю или удаляется по решению пользователя.
- **Защита и монетизация.** Полностью закрыть public-репозиторий от копирования технически невозможно — но и не критично: ценность приложения в его развитии, а релизные сборки публикуем мы. Принципы будущей монетизации (когда дойдём): без серверов и подписок для разработчика, полный офлайн, без привязок к IMEI/учёткам. Рабочая схема: бесплатная базовая версия навсегда + расширенный набор функций (ИИ-модули), включаемый одноразовой покупкой вне приложения (например, через Boosty/личный перевод) с офлайн-кодом разблокировки (локальная проверка хеша кода + идентификатора устройства пользователя, без сети). Код хранится в state и не мешает offline-first. «Пробный период» офлайн технически обходится сбросом данных, поэтому выбран вариант «бесплатное ядро + платное расширение», а не trial по времени. Юридическая часть: в репозиторий добавить LICENSE «все права сохранены» (сейчас UNLICENSED в package.json) — копировать и продавать наш код другим будет незаконно, это и есть основная «защита» без технических костылей.
- **Платформы (iOS и прочие).** Целевой путь — PWA-версия через GitHub Pages (бесплатно, public-репо): приложение откроется в Safari, «На экран Домой» — и работает офлайн; обновления прилетают из GitHub автоматически. Честные ограничения PWA-режима: без Android-виджета, нативных напоминаний с кнопкой «+250 мл», системного голосового ввода и SAF-бэкапа (эти функции — Android-фишки; веб-версия деградирует до уведомлений внутри приложения и экспорта файла). Сборка нативного iOS-приложения (SideStore/AltStore, $99/год аккаунт Apple для App Store) — противоречит принципу бесплатности для разработчика, не планируется. Шаг «PWA через GitHub Pages» добавлен в конец дорожной карты как исследование.

# 2.1. Основные возможности (текущая версия)

На текущий момент реализованы:

- трекер выпитой воды с визуальным прогрессом (кольцо);
- быстрые добавления воды (+250 мл, +500 мл) и отмена последнего;
- настройка дневной цели воды;
- умный трекер калорий с текстовым вводом;
- локальный парсер фраз вида «картофель 150г, котлета 1шт»;
- локальная база из 670+ продуктов (ккал на 100 г или на штуку);
- ручное добавление своего блюда с точной калорийностью и сохранение до 30 избранных блюд;
- список съеденного за день с удалением записей;
- прогресс по калориям с дневной целью;
- быстрые добавления типовых блюд;
- система тем: Авто / Светлая / Тёмная (Material 3);
- переключение экранов: Главная / Настройки / Настроить уведомления;
- вечернее напоминание об активности каждый день в выбранное время (по умолчанию 20:00);
- вопрос о включении вечернего вопроса при первом входе в раздел «Активность» на Android; он спрашивает, была ли активность, а отказ не мешает включить его позже в Настройках;
- экран «Настроить уведомления» со статусом разрешений и подсказками для Honor, Huawei, Xiaomi / Redmi / POCO, Samsung, OPPO / realme, vivo / iQOO и других прошивок;
- отдельная кнопка теста уведомления: отправляет проверочное сообщение через 5 секунд, не меняя вечернее расписание;
- утренние мотивирующие фразы: отдельное включение, время и выбор темы (нейтральная, спокойная, здоровье, питание или активность); 60 вариантов на каждую тему и календарь уникальных фраз на 30 дней;
- напоминания о приёмах пищи: завтрак, обед, полдник, ужин, поздний перекус и пользовательские типы с отдельными временем и включателем;
- выбор типа приёма пищи при добавлении еды; запись отменяет его сегодняшнее напоминание;
- журнал активности: прогулки, спорт и активный отдых; тип, длительность в часах с дробью, список за день и сохранение истории;
- готовые варианты активности: пользовательские шаблоны «Кардио 45 мин», «Прогулка» и другие для добавления одним нажатием;
- экспорт и импорт резервной копии (JSON);
- сброс всех данных;
- работа без подключения к Интернету;
- хранение всех данных только на устройстве.

# 3. Архитектура проекта

Проект сделан максимально простым.

```
index.html
    │
    │ HTML-разметка
    ▼
style.css
    │ CSS (Material 3 токены, light/dark)
    ▼
app.js
    │ JavaScript (логика, состояние, парсер)
    ▼
Capacitor 5.7.0
    ▼
Android WebView
    ▼

```

Логика вынесена в отдельный файл `app.js` (в отличие от старого проекта water-filter,
где всё было в одном `index.html`). Это осознанное решение: разделение понятнее
и не усложняет проект.

- вечерний вопрос об активности: первый вопрос в разделе «Активность», включение, время, планирование через Local Notifications; нажатие на уведомление открывает «Активность» для добавления записи, а отметка активности отменяет вопрос на этот день;
- тест уведомления: отдельный одноразовый сигнал через 5 секунд, который не отменяет и не переносит вечерний вопрос;
- утренняя мотивация: отдельный канал Android, настройка времени и темы; 60 офлайн-вариантов для каждой темы и 30 разных фраз, запланированных на ближайшие дни;
- парсер текста еды с базой 670+ продуктов;
- свои и избранные блюда: ручной ввод названия и калорий, быстрое добавление в один тап;
- история итогов дня: вода, калории и минуты активности сохраняются при смене даты;
- статистика: объединяет текущий день с архивом, показывает итоги и графики за выбранный период;
- мост Android-виджета: WebView передаёт в SharedPreferences краткие итоги текущего дня;
- документирование источников пищевых данных: USDA FoodData Central / SR Legacy и Open Food Facts (ODbL);
- экспорт/импорт резервной копии;
- сброс данных;
- навигация и toast.

# 8. Хранение данных

Все данные хранятся локально в localStorage.

Ключи:

| Ключ | Содержимое |
|------|------------|
| `fitflow:state` | данные профиля «Мой профиль» для совместимости со старыми версиями |
| `fitflow:state:<id>` | данные дополнительного локального профиля |
| `fitflow:profiles` | список профилей и текущий активный профиль |
| `fitflow:theme` | выбранный режим темы (`light`, `dark`; отсутствие = Авто) |
| `fitflow:activity-reminder-prompt-seen` | ответ на первый вопрос о вечернем вопросе «Была ли активность?»; не добавляется в резервную копию и сбрасывается вместе со всеми данными |
| `fitflow:terms-accepted-v1` | принятие информационных условий использования; не добавляется в резервную копию и сбрасывается вместе со всеми данными |

### Управление локальными профилями

В окне профилей всегда видны только их названия. Нажатие на название сразу переключает активный профиль. Кнопка-стрелка раскрывает параметры одного выбранного профиля: переименование, удаление дополнительного профиля, а для активного профиля — поле «Ваш вес, кг». Поэтому список остаётся компактным и при большом числе профилей; вес, цели, история и уведомления каждого профиля не смешиваются.

# 10. Парсер продуктов

Фраза разбивается на части по запятым, союзу «и», тире.

Каждая часть разбирается:

1. Ищется количество: число + единица (`150г`, `1 шт`, `250 мл`, `1 ст.л`, `1 стакан`).
2. Имя продукта ищется в базе (самое длинное совпадение).
3. Калории считаются: ккал на 100 г × вес, или ккал × количество штук.

Поддерживаемые единицы:

- г, гр, грамм, кг;
- мл, л;
- шт, штук;
- ст.л, ч.л, стакан, чашка, порция, ложка.

Если количество не указано — считается условная порция (100 г или 1 шт).

Если продукт не найден — показывается подсказка с примером формата.

ИИ-разбор (Gemini / DeepSeek / YandexGPT) — только опциональное дополнение,
в текущей версии не подключён.

# 15. План развития

Приоритет разработки.

## Высокий приоритет

- реальная проверка APK: профили, оба размера виджета, уведомления, голосовой ввод и обновление поверх предыдущей версии;
- проверка управления профилями: переключение, сворачивание параметров, переименование, удаление и раздельность данных.

Отдельный переключатель показа оценки расхода энергии исключён из приоритета: он менял бы только видимость ориентировочной подписи и не влиял бы на питание, цель или данные.

## Зафиксированный порядок новых функций

Пользователь выбрал следующий набор. Каждая задача делается отдельной небольшой версией; SQLite — строго последним:

1. группировка дневника питания по приёмам пищи — **выполнено в 0.1.47**;
2. управление видимостью и порядком карточек на Главной — **выполнено в 0.1.49**;
3. имя активного профиля в Android-виджете — **выполнено в 0.1.51**;
4. история веса и график веса по профилю — **выполнено в 0.1.52**;
5. следующий уровень офлайн-голосового ввода;
6. SQLite с безопасной миграцией накопленной истории и профилей — **последний пункт**.

Android Health Connect, подробная статистика завтраков / обедов / ужинов и остальные идеи рассматриваются только после этого списка.

## Средний приоритет после зафиксированного списка

- Android Health Connect как необязательная синхронизация шагов, тренировок и активных минут;
- подробная статистика завтраков / обедов / ужинов;
- дополнительная доработка компактного / большого виджета по результатам реального теста;
- ИИ-разбор фраз (Gemini / DeepSeek / YandexGPT) как необязательное дополнение.

## Низкий приоритет

- ИИ-разбор фраз (Gemini / DeepSeek / YandexGPT) — опционально, с учётом ограничений в РФ;
- голосовой ввод;
- приложение LifeOps.


## План локального голосового помощника

- лёгкий режим: офлайн распознавание речи, локальные правила команд и обязательное подтверждение;
- продвинутый режим: отдельно скачиваемая модель размером около 1–2 ГБ для сложных свободных фраз;
- модель не входит в APK, может быть загружена с российского зеркала или импортирована файлом;
- до выбора конкретной модели нужно проверить коммерческую лицензию, возможность перераспространения, атрибуцию, разрешение микрофона и требования магазина.


## План персональных целей и расхода энергии

- добровольный профиль: пол, возраст, рост, вес и обычная активность;
- ориентировочная оценка расхода энергии по типу, длительности и интенсивности активности;
- пользователь выбирает режим: фиксированная цель калорий или учитывать активность;
- не менять цель питания автоматически без явного включения режима и без понятного подтверждения.
- необязательная интеграция Android Health Connect: чтение только выбранных пользователем данных активности, без обязательного аккаунта FitFlow.
