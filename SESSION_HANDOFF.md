# Передача разработки FitFlow

Этот файл нужен только на случай, если текущий диалог Arena нельзя продолжить.

## Что передать новому агенту

1. Открыть и прочитать `AI_GUIDE.md`, `PROJECT.md` и этот файл.
2. Выполнить `node test-parser.js` (87 сценариев, ожидается `ALL TESTS PASSED`) и `node test-ui-init.js` (ожидается `UI INIT CHECK PASSED`).
3. Сначала проверить `git status` и `git log --oneline`.
4. Не выполнять Merge PR до завершения всех задач пользователя.
5. Номер версии приложения живёт в `version.txt` в корне репозитория; workflow сборки читает его сам (с 0.2.5). Чтобы выпустить новую версию, не нужно править build.yml — только `version.txt` и код.

- При выпуске версии обновлять три места: `version.txt` (версия сборки в CI), `package.json`, константу `FITFLOW_VERSION` в app.js (она показывается в «О приложении»).

## Важно про GitHub

- Рабочая ветка этой сессии: `arena/019fd0d2-lifeflow-fitness`. Не переключать ветку.
- Пуш изменений в `.github/workflows/` отклоняется GitHub App без permission `workflows` — активный workflow заменяет пользователь вручную по raw-ссылке на `tools/github-workflows/build.yml` (протокол с SHA-256 и размером описан в AI_GUIDE.md).
- После перехода на `version.txt` ручная замена workflow нужна только при нативных изменениях (Gradle, плагины, MainActivity, виджет), а не ради номера версии.
