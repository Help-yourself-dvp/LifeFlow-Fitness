## 1. С чего начать (10 минут)

1. Прочитать этот файл целиком, затем `AI_GUIDE.md` (правила работы с владельцем)
   и `PROJECT.md` (устройство кода).
2. `git status` и `git log --oneline -5` — убедиться, что дерево чистое.
3. Прогнать все три теста, ожидаются `ALL TESTS PASSED` / `UI INIT CHECK PASSED` /
   `FOOD DB CHECK PASSED`:
   ```
   node test-parser.js && node test-ui-init.js && node test-food-db.js
   ```
4. Не выполнять Merge PR и не переключаться на `main` — перенос в `main`
   это самый последний шаг всего проекта.

**Стек.** Ванильные HTML/CSS/JS (без сборщика) + Capacitor + нативный Android
(Java/Kotlin). Основной код — `app.js` (~900 КБ, один файл), разметка —
`index.html`, стили — `style.css`, натив — `android-native/`.
Сборка APK — GitHub Actions по тегу; в песочнице **нет JDK и Kotlin**,
нативный код проверяется только структурно и собирается в CI.

## 2. Что это за приложение

FitFlow — офлайн-трекер здоровья на русском: вода, питание (ручной ввод, умный
разбор фразы, сканер штрих-кода, фото), тренировки и силовой дневник, шаги и сон
из Health Connect, вес, витамины-курсы, виджет на домашнем экране, локальная
нейросеть (опционально).

**Ядро продукта — вода и ручной учёт калорий.** Всё остальное вторично: если
выбор стоит между новой функцией и стабильностью ядра, выбирается стабильность.

**Главный принцип владельца:** «Простое приложение: один раз настроил и
пользуемся». Не городить кнопок, приложение само разбирается. Любое решение,
добавляющее пользователю работу, — плохое решение по умолчанию.

**Никаких видимых заглушек.** Нерабочий элемент либо не добавляется вовсе, либо
добавляется полностью скрытым (`hidden`). Полурабочих кнопок в UI быть не должно.

## 3. Как работать с владельцем

Подробно — в `AI_GUIDE.md`, здесь самое важное:

- **Принцип обратной связи.** Замечания владельца — это предложения к
  обсуждению, а не приказы. Отвечать **по каждому пункту** развёрнуто и спорить

  описывать функции, которых нет в коде.

  шагами. Ссылки — кликабельными полными URL; ссылки на правку файлов GitHub —
  в режиме `/edit/<ветка>/<путь>`.
- **Одна версия = одна небольшая законченная задача.**

## 5. Постоянные требования владельца

Их нельзя нарушать без явной отмены владельцем:

- **Перенос в `main` — самый последний шаг проекта.** Merge PR до завершения
  всех задач не делать.
- **Офлайн по умолчанию.** Онлайн-функции — только явно включаемая опция.
  Статус онлайн/офлайн виден в верхней панели рядом со значком приложения.
- **Бета-метки** обязательны у: прогресса силовых, ИИ-рекомендаций, ИИ-статистики.
- **Функцию распознавания фото еды не удалять.**
- **Уменьшать APK только без потерь** функциональности, скорости и корректности
  данных.
- **Сканер штрих-кода — только камерой** (ручной ввод кода отвергнут), источник
  данных бесплатный и без зависимости от Google Play Services (выбран ZXing +
  Open Food Facts). Сканер пишет съеденное **сразу в текущий приём пищи**,
  подставляя полный вес продукта. Разовые покупки не засорять «Моими продуктами».
- **Тип приёма пищи можно менять в уже записанном приёме.**
- **«Тренировки» из обычной ходьбы, которые создают часы, оставлять как есть** —
  это реальная активность, пусть идёт в недельную цель.
- **Критерий «дубль по одинаковой длительности ±15 мин» отвергнут:** несколько
  тренировок в день похожей длительности — норма. Определять дубль автоматически
  по пересечению интервалов (сделано в 0.9.10).
- TalkBack — только базовые правки. Магазин — RuStore.
- В пилюлях быстрого перехода — только текст, без иконок.
- Юридическая информация — в существующий раздел лицензии в настройках.
- Правки в `build.yml` — одним разом, объединяя все изменения.

## 6. Технический минимум

### Версия правится в 4 местах одновременно
Иначе падает тест «версия в коде и в „О приложении“ совпадают»:
1. `version.txt` (строка 1) — workflow читает её сам;
2. `app.js` — `const FITFLOW_VERSION` (~строка 3054);
3. `index.html` — `#about-version` (~строка 1350);
4. `APP_DESCRIPTION.md` — строка 3.

### Протокол замены workflow (делает владелец, с телефона)
Пуш в `.github/workflows/` запрещён GitHub App (403), `workflow_dispatch` тоже.
Активный workflow заменяет владелец вручную по зеркалу:

1. Скопировать зеркало целиком:
   https://raw.githubusercontent.com/Help-yourself-dvp/LifeFlow-Fitness/arena/01a02da3-lifeflow-fitness/tools/github-workflows/build.yml
2. Открыть активный workflow в режиме редактирования и заменить всё содержимое:
   https://github.com/Help-yourself-dvp/LifeFlow-Fitness/edit/arena/01a02da3-lifeflow-fitness/.github/workflows/build.yml
3. Commit changes → вкладка «Actions» → дождаться сборки → APK в Releases.

Замена нужна **только если менялся нативный код или сама сборка**. Правки
JS/HTML/CSS собираются обычным релизом.

### Коммит и проверка сборки
`git add -A` захватывает `.github/workflows/build.yml` — **коммитить явным
списком файлов**. Проверка сборки:
```
gh run list --branch arena/01a02da3-lifeflow-fitness --limit 5 --json databaseId,status,conclusion,headSha
gh run watch <ID> --exit-status --interval 20
gh release list --limit 2
```
`gh run view --log` возвращает пусто, APK из песочницы не скачать — проверять
по `conclusion: success` и списку ассетов релиза.

## 7. Грабли, на которые уже наступали

Список короткий, но каждый пункт стоил отдельной итерации.

### 7.1. Колбэк из натива не найдётся, если функция не присвоена в `window`
Объявление `function onHealthSleepHistoryReceived(...)` внутри модульной области
недостаточно: мост зовёт `window.<name>`. Образец правильного подключения —
`app.js` рядом со строкой 8134. Каждую новую мост-функцию проверять
`grep -n "window\.onHealth.*=" app.js`.
**Известный незакрытый случай:** `onHealthBodyMetricsReceived`.

### 7.2. Health Connect отдаёт данные постранично
`readRecords` возвращает до 1000 записей за страницу плюс `pageToken`. Без цикла
`do { … } while (pageToken != null)` часть данных теряется молча. Именно это
оставило шаги за 20–21 августа пустыми в 0.9.11: часы пишут шаги мелкими
кусками, лимит выбирался на старых днях. У сна записей мало, поэтому он прошёл.
**Любое новое чтение истории из HC — сразу с пагинацией.**

### 7.3. Шаги: часы и телефон нельзя складывать
`syncNow` считает их раздельно через `WEARABLE_PACKAGES` и отдаёт приоритет
часам. При правках агрегации шагов сверяться с `syncNow`
(`HealthConnectHelper.kt`, строки ~60–90).

### 7.4. Старые тесты могут кодировать неверное поведение
Падение теста — это конфликт намерений, а не «сломанный тест». Сначала выяснить,
почему правило введено, починить корень, и только потом переписывать ожидание —
с комментарием, почему прежнее было ошибочным.

### 7.5. Тест обязан падать без фикса и не падать аварийно
- Прогонять **все три** теста по exit-коду; прогон только «своего» маскирует регрессии.
- **Верификация откатом** — обязательный шаг перед коммитом:
  ```
  cp app.js /tmp/app.new
  git show HEAD:app.js > app.js
  node test-ui-init.js          # новые проверки должны показать ✗
  cp /tmp/app.new app.js
  ```
- Если функции ещё нет в `module.exports`, `require` роняет весь прогон и тест
  бесполезен. Ставить guard (`const hasApi = typeof api.foo === 'function'`).
- Жадный regex даёт ложно проходящий тест (`combo: '([^']+)'` ловил постороннее
  `combo: '⭐'`). Сначала вырезать нужный блок, потом искать внутри.
- Поведенческий тест без jsdom: вырезать тело функции срезом по `indexOf` и
  исполнить через `new Function(...deps, src + '; return fn;')`.
- В jsdom нельзя обращаться к `window.state`; стенды делать через
  `runScripts: 'dangerously'` и шим `$`.

### 7.6. Правки большого файла — только с уникальным контекстом
Замена по первому вхождению бьёт по чужому блоку. Адресоваться длинным
уникальным контекстом и проверять `assert s.count(old) == 1`.

### 7.7. Кириллица в правках
- Вставка русских комментариев иногда вносит случайные CJK-символы. После каждой
  записи проверять:
  ```
  python3 -c "import io;s=io.open('app.js',encoding='utf-8').read();print([c for c in s if '\u4e00'<=c<='\u9fff'])"
  ```
- `cat -v` и `sed` искажают кириллицу — сверять `python3` + `repr()`.
- Последовательность `*/` внутри блочного комментария закрывает его досрочно
  (`x/х/*/×` в комментарии ломала файл). Писать словами.

### 7.8. Прочее
- `app.js` грузится через `require` в чистом Node: верхнеуровневые обращения к
  `window`/`document` роняют `test-parser.js`.
- Java-методы не объявляются через `fun` — regex `/fun <name>/` по
  `MainActivity.java` даёт ложный ✗; использовать `/void <name>\(\)/`.
- Клик внутри `.collapsible-toggle` сворачивает блок — интерактивное класть в
  `.collapsible-content`.
- Видимость карточек — `state.homeLayout.visible[id]`, не `state.trackers`.
  Онлайн-флаги — `state.onlineFeatures`.
- `fetch` из WebView не задаёт `User-Agent` — для Open Food Facts использовать
  query-параметры `app_name` / `app_version` / `app_uuid`.
- `/tmp` между сессиями очищается — все проверки переносить в `test-ui-init.js`.
- Не писать имена функций по памяти — сначала `grep`.
- **Локальный HEAD дважды самопроизвольно откатывался** при сохранном рабочем
  дереве. Лечение без потери работы:
  ```
  tar czf /tmp/bk-tree.tgz --exclude=.git .
  git fetch origin arena/01a02da3-lifeflow-fitness
  git reset FETCH_HEAD          # без --hard
  ```

### 7.9. Кнопки уведомлений Capacitor всегда открывают приложение
`@capacitor/local-notifications` на Android игнорирует `foreground: false`:
в `LocalNotificationManager.createActionIntents` и contentIntent, и каждое
action-`PendingIntent` создаются через `PendingIntent.getActivity()` с
`ACTION_MAIN` + `CATEGORY_LAUNCHER`. Если нужно действие «в фоне» (подтвердить
приём, добавить воду) — только свой `BroadcastReceiver` + `AlarmManager`,
образцы: `WaterReminderReceiver.java`, `CourseReminderReceiver.java` (0.9.13).
Отметка, сделанная нативом без приложения, кладётся в очередь и доезжает в
app.js на `onResume` — доставку обязательно повторять до `window.__fitflowReady`,
иначе на холодном старте она потеряется до следующего запуска.

### 7.10. Новый нативный класс = правка workflow
До 0.9.13 шаг «Копировать нативные исходники» перечислял файлы поимённо.
Класс, добавленный в `android-native/` без правки списка, просто не попадал

обязательные файлы. Пока владелец не перенёс зеркало в
`.github/workflows/build.yml`, активный workflow остаётся старым: пуш в
`.github/` запрещён GitHub App, замена — вручную по raw-ссылке.

zip даёт 0 байт) — диагностировать по имени упавшего шага
(`gh run view <ID> --json jobs`) и перекрёстной сверке символов `grep`.
